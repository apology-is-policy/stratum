## P1 — actionable

- **test_multi_stratumd_crash.c:373-377 — Test 2's `STM_ASSERT(!probe_ok)` admits the hang regression it claims to catch.** A coord-crash regression where the proxy worker hangs waiting on a never-arriving downstream reply manifests as: `read()` blocks → `SO_RCVTIMEO=3s` fires → `read()` returns -1 / EAGAIN → `do_tflush_probe` returns `false` → `STM_ASSERT(!probe_ok)` PASSES. The test is observationally indistinguishable from the CORRECT path (immediate EOF from upstream EPIPE → read returns 0 → returns false → assert passes). The two behaviors differ only in elapsed wall time (clean disconnect: ≪100 ms; hang regression: ~3000 ms). Suggested fix: bracket the probe with `clock_gettime(CLOCK_MONOTONIC, ...)` and assert `elapsed < 1.0s` (or some bound ≪ SO_RCVTIMEO) in addition to `!probe_ok`. Without this, the test passes for the very class of regression — proxy worker hanging on coord death — that motivated the chunk per design §10. Carrying as P1 because the entire purpose of Test 2 is undermined.

## P2 — actionable

- **test_multi_stratumd_crash.c:409-414 — Test 3's 32-cycle threshold is too small AND probes the wrong invariant.** Each accepted connection on coord allocates a FRESH `stm_9p_server` with a FRESH `fids[STM_9P_MAX_FIDS=4096]` table; the per-conn fid table is freed in lockstep with the server struct. A regression that fails to free the `stm_9p_server` on disconnect leaks memory + thread state, not "fids" — the next dial gets a fresh fid table regardless. The "fid-cap exhaustion" Test 3 claims to indirectly probe is unreachable via this loop. 32 cycles in <300 ms also wouldn't surface (a) a per-cycle 1-fid leak inside a single server (no server is reused across cycles), nor (b) a per-cycle thread/memory leak that needs hundreds to thousands of cycles to manifest as failure. Suggested: rename the test + assertion to what's actually being verified ("fresh dial after abrupt close still handshakes"); for actual leak detection, run under valgrind/ASan with a higher cycle count (≥1000) and assert on RSS growth or use `pthread_attr_getstack` to verify all detached workers exited (the latter requires impl-side instrumentation). At minimum: bump the cycle count to e.g. 200 + correct the docstring's "STM_9P_MAX_FIDS (4096); without cleanup we'd leak per cycle" claim — that sentence is misleading.

- **test_multi_stratumd_crash.c:336-338 — Test 1's Tflush probe verifies the connection is parseable, NOT that the FS-backed surface still works.** The Tflush handler at `v2/src/9p/server.c:1162-1176` is a stateless no-op that never touches the FS, allocator, or any per-conn fid state — it just emits Rflush. A regression that breaks client_B's downstream FS connection BUT leaves the proxy's framing intact (e.g., client_A's death corrupts coord's shared sync/scrub state but coord's per-conn 9P server still parses frames) would slip through. The R96 / spec `ClientCrashIsolation` invariant is about real fs-state isolation, not wire-framing health. Suggested: extend Test 1 with a Tattach (admits the conn into the FS namespace) + Twalk on `/` (exercises root inode lookup) on client_B after client_A's kill — proves FS-side is still serving, not just that the wire's alive. The current Tflush probe is a useful smoke-test but not a load-bearing assertion.

- **test_multi_stratumd_crash.c:312-318, 350-356, 392-398 — STM_STRATUMD_BIN-unset SKIP silently counts as PASS.** When the env is unset (e.g., running `./test_multi_stratumd_crash` directly, NOT via ctest), each test prints "SKIP" to stderr but returns without setting `stm_test_current_failed`, so the harness counts it as "ok". A CI rig that invokes the binary directly (rather than via `ctest`) would report green for 3 tests that never ran. CMakeLists sets the env via `ENVIRONMENT` ctest property at line 109-110, so the normal `cmake --build && ctest` path is fine — but a `make test` from a partial-build tree, or a custom CI script that loops over `build/tests/test_*`, would silently pass. Suggested: at minimum exit nonzero from the SKIP path when env is unset, OR print a summary line "SKIPPED N tests due to STM_STRATUMD_BIN unset" at the end of the suite, OR fail-by-default with an opt-out env (e.g., `STM_STRATUMD_BIN_SKIP_OK=1`). The current posture trades a real signal for clean test output.

- **test_multi_stratumd_crash.c:144-157 — `dial_unix` lacks SO_RCVTIMEO/SO_SNDTIMEO, so a coord that accept()s but never writes hangs the test indefinitely.** The ctest TIMEOUT=60 (CMakeLists:110) is the only backstop — within the 60s window, a hung Tversion would burn time silently. Test 2 adds explicit timeouts ONLY after the coord is killed; the initial Tversion in lines 326/330/362/411-412 has no timeout. A regression where coord/client accepts but doesn't reply to Tversion (e.g., a refactor that mis-spawns the per-connection worker) hangs each affected test for ~60s before ctest kills it. Suggested: factor a `dial_unix_with_timeout(path, ms)` helper and use it everywhere, set 5-10s on all dials.

- **test_multi_stratumd_crash.c:218-235 — orphaned `/tmp/stm_crash_*_*.sock` files persist on test-process SIGSEGV/SIGABRT.** STM_ASSERT failures correctly fall through to `crash_fixture_teardown` (verified via `tharness.c:22-30` — sets a flag, no longjmp/exit). But a real crash (e.g., libsodium null-deref under ASan inside the test process) skips teardown; spawned subprocesses become orphans (reparented to init/launchd) and the socket files stay in /tmp. Per-pid paths via `getpid()` prevent collision *within* a test run but cross-run `/tmp` accumulation is real — over many CI iterations, /tmp grows. Suggested: also `unlink(2)` in an `atexit` handler installed once per test binary, OR move the socket/fs paths to `${CMAKE_BINARY_DIR}/test_tmp/` (auto-cleaned on clean rebuild) instead of `/tmp/`.

## P3 — forward-notes

- **test_multi_stratumd_crash.c:74-82 — stderr suppression hides ASan/UBSan diagnostics from spawned subprocesses.** `STM_CRASH_VERBOSE=1` reopens stderr, but the default route to `/dev/null` means an ASan stack from a crashing stratumd subprocess is invisible. Under sanitizers (the CI default per `stm_sanitize` interface lib at CMakeLists:13), this defeats half the point of running tests under ASan. Forward-note: invert the default — keep child stderr open, gate suppression behind `STM_CRASH_QUIET=1` for local dev. v1.1 candidate.

- **test_multi_stratumd_crash.c:93-116 — `wait_for_socket` returns true on `connect()` success but doesn't verify accept() has completed.** Small race: between connect-success and the test's subsequent dial, the daemon could exit (e.g., bind+listen succeeded but the accept-thread spawn failed). connect-then-immediate-disconnect would surface as a failed Tversion downstream. Unlikely in practice (the daemon's accept loop runs on the calling thread of run() — see `serve.c::stm_stratumd_run`), so the bind+listen succeeding means accept is imminent. Forward-note only.

- **test_multi_stratumd_crash.c:206 — `MAX_CLIENTS=4` is plenty for current tests but a future Thylacine multi-tenant test (10+ per-user stratumds) needs more.** Trivial bump when needed. Forward-note.

- **General — no test exercises `wedge_cause` after a crash.** The spec `multi_stratumd.tla::ClientCrashIsolation` says `wedge_cause = "Crash"` must be unreachable. The impl achieves this by NEVER setting wedge_cause from the coord/proxy crash paths (only fs-level commit failure can wedge). No test directly probes coord's stm_fs wedge state after a client crash via /ctl/state or the `stm_fs_stats_get` wedged flag. Adding a post-crash `stm_fs_stats_get` check on the coord's fs would convert the implicit "if it didn't wedge, we didn't break the invariant" into an explicit assertion. Forward-note for impl-5 stress or a follow-up close test.

- **Test 1 has no assertion that the coord-side per-conn for client_A was actually cleaned up.** The test only asserts client_B's conn still works — passive. A regression where coord leaks per-conn state on client_A's disconnect but doesn't disturb client_B would silently pass. R96 already covers `stm_9p_server_destroy` cleanup; this audit's chunk doesn't claim to re-prove that. Forward-note: pair with a /ctl/-readable per-conn-count gauge if one exists or gets added.
